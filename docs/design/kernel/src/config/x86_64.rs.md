# `kernel/src/config/x86_64.rs`

> 对应源码：`kernel/src/config/x86_64.rs`
> 所属：配置 / 架构常量（x86_64）
> 状态：编译支持（README 标注 "work in progress"），不参与竞赛构建

## 1. 文件职责

x86_64 的用户态地址布局。与 RISC-V/LoongArch 的差异只有两个常量。

## 2. 常量表

| 常量 | 值 | 与 rv/la 的差异 |
|---|---|---|
| `KERNEL_STACK_SIZE` | `0x4_0000` | 相同 |
| `USER_SPACE_BASE` | `0x1000` | 相同 |
| `USER_SPACE_SIZE` | `0x7fff_ffff_f000` | **更大**（47 位用户空间） |
| `USER_STACK_TOP` | `0x7fff_0000_0000` | **更高**（≈128TiB 处） |
| `USER_STACK_SIZE` | `0x8_0000` | 相同 |
| `USER_HEAP_BASE` | `0x4000_0000` | 相同 |
| `USER_HEAP_SIZE` | `0x1_0000` | 相同 |
| `USER_HEAP_SIZE_MAX` | `0x2000_0000` | 相同 |
| `USER_INTERP_BASE` | `0x400_0000` | 相同 |
| `SIGNAL_TRAMPOLINE` | `0x6000_1000` | 相同 |

## 3. 不变量与约束

- `USER_SPACE_SIZE` 与 `USER_STACK_TOP` 必须满足 `STACK_TOP < BASE + SIZE`：`0x7fff_0000_0000 < 0x8000_0000_0000`。
- 用户栈位于高地址，`mm/access.rs::check_access` 的边界检查依赖这两个常量；改小 `USER_SPACE_SIZE` 会让高地址栈访问被误判为非法。
- x86_64 需要 `copy_from_kernel`（非 aarch64/la64 分支），本文件不涉及。
- 与 `syscall/mod.rs` 的 `#[cfg(target_arch = "x86_64")]` 分支（`open/stat/fork/dup2/...`）配套；本文件只负责地址布局。

## 4. 已知局限 / TODO

- x86_64 目前只有编译级支持（README 的 Supported Architectures 未勾选）。
- 没有针对 5 级页表/LA57 的考虑。
- 若将来启用，需要补 `page_table_multiarch`（已在 `kernel/Cargo.toml` 的非 aarch64/la 分支）与 `x86` crate 的 `gs_base` 处理（见 `syscall/task/thread.rs` 的 `arch_prctl`）。
